                    404 STATUS ENDPOINT FIX - COMPLETE PACKAGE
================================================================================

PROBLEM:
When client polls the status endpoint, it gets 404 Not Found error because
Lambda's in-memory cache is lost between invocations.

ROOT CAUSE:
Lambda is stateless. Each invocation is a separate process with fresh memory.
The image stored in Invocation #1 is lost when Invocation #2 starts.

SOLUTION:
Use DynamoDB for persistent storage instead of just in-memory cache.

                            IMPLEMENTATION STEPS

STEP 1: Create DynamoDB Table (2 minutes)
  aws dynamodb create-table \
    --table-name fulmine-sparks-images \
    --attribute-definitions AttributeName=payment_hash,AttributeType=S \
    --key-schema AttributeName=payment_hash,KeyType=HASH \
    --billing-mode PAY_PER_REQUEST \
    --region us-east-2

STEP 2: Update Lambda IAM Permissions (2 minutes)
  - Get Lambda role name
  - Add DynamoDB permissions (GetItem, PutItem, UpdateItem, DeleteItem)

STEP 3: Update 5 Functions in Code (15 minutes)
  1. store_image() - Add images_table.put_item()
  2. get_cached_image() - Add images_table.get_item() fallback
  3. get_image_status() - Add images_table.get_item() fallback
  4. mark_image_available() - Add images_table.update_item()
  5. delete_cached_image() - Add images_table.delete_item()

STEP 4: Create & Upload Deployment Package (5 minutes)
  - Create zip with updated code
  - Upload to Lambda

STEP 5: Set Environment Variable (1 minute)
  - Set IMAGES_TABLE=fulmine-sparks-images

BEFORE (Broken):
  Invocation 1: Generate image → Store in memory ✅
  Invocation 2: Poll status → 404 ❌
  Invocation 3: Poll status → 404 ❌
  Invocation 4: Retrieve → 404 ❌

AFTER (Fixed):

  Invocation 2: Poll status → Read from DynamoDB ✅

  Invocation 4: Retrieve → Read from DynamoDB ✅
