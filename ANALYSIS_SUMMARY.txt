PROJECT: Fulmine-Sparks - Serverless AI Image Generation API with Lightning Payments

DESCRIPTION:
A production-ready serverless API that generates AI images using SeeDream 4.5
model and accepts payments via Bitcoin Lightning Network. Includes sophisticated
rate limiting, dual-layer caching, and comprehensive documentation.

TECH STACK:
- Backend: AWS Lambda (Python)
- API: API Gateway (HTTP)
- Storage: DynamoDB + In-memory cache
- Image Generation: Replicate API
- Payments: Alby Hub NWC (Lightning Network)

================================================================================
                            CURRENT ISSUES
================================================================================

🔴 HIGH PRIORITY ISSUES:

1. Debug Logging in Production
   - Multiple DEBUG print statements left in code
   - Exposes internal structure in CloudWatch logs
   - Should use proper logging module
   - Effort: 30 minutes

2. DynamoDB Integration Incomplete
   - Code initializes DynamoDB but never uses it
   - Images only stored in memory cache
   - Lost between Lambda invocations
   - Defeats purpose of persistent storage
   - Effort: 1 hour

🟡 MEDIUM PRIORITY ISSUES:

3. Path Extraction Complexity
   - Recent commits show ongoing debugging issues
   - Multiple fallback attempts for path parsing
   - Stage prefix stripping is fragile
   - Effort: 45 minutes

4. No Request Signing
   - Anyone with payment hash can retrieve image
   - No authentication for sensitive endpoints
   - Should implement HMAC-SHA256 verification
   - Effort: 1 hour

5. Rate Limiting Not Persistent
   - In-memory tracking lost between invocations
   - Could be bypassed with multiple IPs
   - Should use DynamoDB for persistence
   - Effort: 1.5 hours

🟢 LOW PRIORITY ISSUES:

6. No Monitoring/Metrics
   - Missing CloudWatch metrics collection
   - No performance tracking
   - Effort: 1 hour
